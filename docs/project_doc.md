# Scholar Agent — 项目文档

> 第八届中国研究生人工智能创新大赛（华为赛题三）
> 团队成员：人A（算法/创新）、人B（工程/评测）

---

## 1 项目概况

### 1.1 背景和基础

**赛题背景**：第八届中国研究生人工智能创新大赛华为赛题三要求构建"面向复杂学术查询的智能论文检索与推荐系统"。核心挑战在于，现有学术搜索引擎（Google Scholar、Semantic Scholar）在处理复杂、细粒度的学术查询时效果不佳——它们通常依赖关键词匹配，无法理解查询中的方法对比、数据集约束、前沿追踪等深层语义。

**项目灵感**：学术文献检索是科研工作中最耗时的环节之一。研究生在进行文献调研时，经常需要提出如"基于Transformer的医学图像分割方法与U-Net的对比分析"这类复杂查询，传统搜索引擎无法有效处理。我们决定构建一个 LLM Agent，通过多维度理解查询意图、多策略搜索、细粒度相关性评估来解决这一问题。

**已有工作基础**：
- **PaSa** (ACL 2025): 使用 LLM Agent 进行学术论文搜索，提出了双层搜索架构。但 PaSa 依赖特化的 7B 模型，且仅支持单轮查询分解。
- **SPAR** (arXiv 2025): 利用结构化查询规划提升学术搜索精度，但缺乏跨查询的经验复用机制。
- **LitSearch** (EMNLP 2024): 多粒度文献检索数据集，已用于评测。
- **AutoScholarQuery** (2025): 包含 3500+ 条复杂学术查询的公开数据集，提供标准评估基准。

**团队构成**：
- 人A：负责核心算法设计（Crawler/Selector 双智能体架构、Claim 级分解算法、全文解析策略）
- 人B：负责工程实现（数据管道、评测体系、Docker/文档、演示视频）

### 1.2 场景和价值

**适用场景**：
- 研究生文献调研：输入"对比 ViT 和 CNN 在医学影像中的表现"即可获得结构化结果
- 跨学科研究：处理"图神经网络在药物发现中的应用"等跨领域查询
- 系统文献综述：自动检索、分类、筛选相关论文，辅助综述撰写
- 前沿追踪：自动追踪某领域的最新进展

**市场调研**：
- **Google Scholar**：依赖关键词匹配，无法理解"对比"、"优势"、"局限性"等语义关系，结果排序不透明
- **Semantic Scholar**：API 限制严格（非商业用途），缺乏细粒度查询理解
- **PaSa**：基于 LLM 但需特化微调，泛化能力受限
- **Ai2 Paper Finder**：仅支持单篇论文查找，无批量检索和比较能力

**对比分析**：

| 维度 | Scholar Agent | PaSa | SPAR | Google Scholar |
|------|--------------|------|------|----------------|
| 查询理解 | LLM 多维分解 | 单轮分解 | 结构化规划 | 关键词匹配 |
| 搜索策略 | Multi-Crawler | 双层搜索 | 单策略 | 关键词搜索 |
| 相关性评估 | Claim 级细粒度 | 整体评分 | 规则评分 | 引用数排序 |
| 跨查询记忆 | SearchMemory | 无 | 无 | 无 |
| 全文验证 | FullTextAnalyzer | 无 | 无 | 无 |
| 领域适应性 | 零样本（无需微调） | 需特化训练 | 需少量调参 | 通用 |

**社会价值**：
- 提升科研效率：将文献调研时间从数天缩短到数分钟
- 降低检索门槛：非英语母语研究者也能通过自然语言查询获取精准结果
- 促进跨学科研究：帮助研究者快速了解邻近领域的最新进展

### 1.3 所需支持

**算力**：
- LLM API 调用（DeepSeek）：单次查询约 10-20 次调用，约 3000-5000 tokens
- 本地测试环境：Python 3.11，无需 GPU
- Docker 构建：约 500MB 镜像大小

**数据**：
- AutoScholarQuery 公开数据集（3500+ 查询，含训练/验证/测试集）
- RealScholarQuery 真实用户查询集

## 2 项目规划

### 2.1 整体目标

- 构建可演示的端到端学术论文智能搜索原型系统
- 在 AutoScholarQuery 上 F1 超过 PaSa 基线（PaSa: Recall@20=0.524）
- 支持中英文复杂学术查询
- 提供完整评测体系和消融实验验证
- 模块化设计，便于后续扩展

### 2.2 技术创新点

**创新点 1：Multi-Crawler 并行搜索架构**

传统搜索 Agent 使用单一搜索策略，无法覆盖复杂查询的多个维度。我们的 Multi-Crawler 架构：
1. 由 DimensionAnalyzer 将查询分解为多个独立维度（topic / method / dataset / survey / application / comparison）
2. 每个维度生成专用的搜索查询
3. 并行执行多策略搜索，覆盖不同信息维度
4. 通过 ResultMerger 进行模糊标题去重（SequenceMatcher > 0.85）
5. 记录每个来源的搜索维度，提供可追溯性

效果：召回率显著提升，尤其对多维度复杂查询效果明显。

**创新点 2：Claim-level 细粒度打分**

传统方法对论文进行整体相关性评分，无法解释"为什么这篇论文相关"。我们的方法：
1. ClaimExtractor 将查询分解为 3-6 个独立可验证的 Claim
2. 每个 Claim 附带 required/bonus 分类和权重
3. Selector 对每篇论文的每个 Claim 独立评估（satisfied + confidence）
4. 综合各 Claim 得分计算论文总分（加权融合）
5. 通过 Gap Analysis 识别未被满足的 Claim，驱动补充检索

效果：精确率和可解释性双提升。用户能看到"这篇论文满足了你关注的哪几个方面"。

**创新点 3：全文解析 + 深层引文追踪**

传统 Agent 仅依赖论文元数据，无法利用正文中的深层信息。FullTextAnalyzer：
1. 从 OpenAlex / Semantic Scholar 获取 OA PDF URL
2. 使用 PyMuPDF (fitz) 解析 PDF 章节结构
3. 从参考文献章节提取论文标题
4. 将提取的参考文献作为新搜索查询（深层引文追踪）
5. 在正文中搜索 Claim 关键词，验证论文是否真正满足 Claim

效果：隐藏关联论文被发现率提升，排序置信度增强。

**创新点 4：搜索经验记忆**

传统搜索 Agent 每次查询都从零开始，无法利用历史经验。SearchMemory：
1. 将查询分为 5 类：survey / method_comparison / specific_dataset / frontier_tracking / application
2. 每次搜索后记录：查询类型 + 使用策略 + 预估召回率/精确率
3. 下次遇到同类查询时，自动推荐历史上效果最好的策略
4. JSON 文件持久化，轻量无依赖

效果：冷启动后策略命中率逐步提升，同类查询效果持续优化。

## 3 实施方案

### 3.1 技术可行性分析

**数据来源**：
- **Semantic Scholar API**：免费 API，提供论文元数据、引用关系、嵌入向量
- **OpenAlex API**：完全免费开放，覆盖 2.5 亿+ 学术论文
- 双数据源互为备份，防止单点故障

**LLM 调用**：
- 使用 DeepSeek API（价格便宜，性能优异）
- 单次查询 token 消耗可控：DimensionAnalyzer ~500, Crawler ~800, Selector ~200/paper
- 典型场景单次查询约 3000-5000 tokens

**可复现性**：
- 所有依赖通过 pyproject.toml 管理
- Docker 容器化部署
- 评测脚本一键运行
- GitHub 版本管理（git tag v1.0 ~ v6.0）

### 3.2 技术细节

**系统架构**

**各模块技术细节**：

| 模块 | 输入 | 核心逻辑 | 输出 |
|------|------|---------|------|
| DimensionAnalyzer | 用户查询 | LLM 分析查询维度、关键词、优先级 | 维度列表 + 必含词 |
| Crawler | 查询文本 | LLM 生成搜索策略 / 查询演化 | 搜索计划 / 新查询 |
| Retriever | 查询文本 | OpenAlex / Semantic Scholar API 调用 | 论文列表 |
| ResultMerger | 多维度结果 | 模糊标题去重 + 来源追踪 | 唯一论文集合 |
| ClaimExtractor | 查询文本 | LLM 分解可验证断言 | Claim 列表 |
| Selector | 论文 + Claim | LLM 逐 Claim 评估 + 加权融合 | 评分论文列表 |
| FullTextAnalyzer | 论文 + PDF | PDF 解析 + 正文关键词验证 | 验证结果 |
| SearchMemory | 查询文本 | 分类 → 检索历史 → 推荐策略 | 策略列表 |

**预期技术指标**：
- Recall@20 > 0.5（超过 Google + GPT-4o 的 0.385）
- F1 > 0.4
- 单次查询时间 < 120 秒
- 支持中英文查询

## 4 参考资料

1. **PaSa: An LLM Agent for Comprehensive Academic Paper Search** — ACL 2025
   - 启发：LLM Agent 用于学术搜索的可行性
   - 差异：我们使用通用 LLM + 多策略搜索，而非特化 7B 模型

2. **SPAR: Structured Query Planning for Literature Search** — arXiv 2025
   - 启发：查询结构化分解提升搜索精度
   - 差异：我们增加跨查询记忆和全文验证

3. **LitSearch: A Multi-Granularity Literature Search Dataset** — EMNLP 2024
   - 启发：学术搜索评测标准
   - 使用：AutoScholarQuery 数据集（同源）

4. **AstaBench: Can LLMs Match Academic Paper Finders?** — 2025
   - 启发：LLM 与专用搜索系统的对比
   - 差异：我们结合 LLM 理解和专用搜索的优势

5. **SearchAgent: Two LLM-Based Agents for Information Retrieval** — 2024
   - 启发：Crawler-Selector 双智能体架构
   - 实现：基于此架构扩展了 Multi-Crawler 和 Claim-level 机制
